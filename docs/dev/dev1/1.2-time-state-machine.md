## 迭代目标

从 ACTIVE 状态自动进入 WARNING 状态，不依赖倒计时，而依赖绝对时间。开发时用 30 秒测试模式，正式用 35 分钟生产模式。

## 实现说明

### 绝对时间模型

`warningTime = startTime + timeout`，状态判断是 `now >= warningTime`，Apple 的时间权威在 iPhone 侧，不保存也不用倒计时程序。App 被后台挂起或终止后，从 UserDefaults 恢复 startTime / warningTime / state，再重算剩余，状态不会漂移（story-1.2 R1.2.4）。

### 30 秒 vs 35 分钟

参数集中在 `Timeouts.swift`，开发阶段 `currentMode = .development`（30 秒），闭环跑通后 story-3.2 切到 `.production`（35 分钟）。切换只改参数不改架构（rfc ADR-004）。

### 到点提醒双保险

一是 App 前台/恢复时 recomputeStateIfNeeded 把状态切到 WARNING（1 秒轻量重算驱动只是重新评估绝对时间，不是倒计时）。二是按 warningTime 调度一条本地通知作兜底，App 在后台时用户也能被提醒。
