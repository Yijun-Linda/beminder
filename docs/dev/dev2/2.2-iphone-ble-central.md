## 迭代目标

iPhone App 作为 BLE（Bluetooth Low Energy，低功耗蓝牙）主设备（Central），扫描、发现并连接 FoloToy，把 Session 状态写入设备。

## Bug 追踪

本迭代功能产生 bug 时在此记录修复进度。每条记录包含日期、现象、根因、修复、验证。

### 2026-08-22：闭包内误用 session 而非 self.session

现象：observeFoloToy 与 observeFoloToyConnection 的闭包里直接写 `session.state` / `session.foloToyConnected`，未加 self 前缀。

根因：NotificationCenter closure 里有 `guard let self`，但在其中一处漏用 self 访问实例属性。

修复：SessionManager 中统一用 self.session，闭包内均通过 self 访问。

验证：静态核对所有 self 捕获与属性访问。IOS 无真实编译环境，需在 Mac/Xcode 真机验证，Android/Windows 不适用。

### 2026-08-25：didDiscover 广播名过滤过宽

现象：BLEManager 扫描回调里 `guard name == BeminderBLE.advertisementName || name != nil` 恒真，等价于"任何有广播名的设备都连接"，语义错误（code_review_ocr_delegation 审计项，此前未修）。

根因：写条件时把"广播名取不到就回落到 service 过滤"的意图错误实现为 `|| name != nil`，后者永远为真。

修复：收紧为"名字存在但匹配不上 Beminder 则跳过；名字为 nil（iOS 尚未解析广播名）时依赖上面的 serviceUUID 扫描兜底"。

验证：静态核对。真机需确认扫描时不会误连其他广播 BLE 设备。

### 2026-08-25：App 后台时 WARNING 不下发 FoloToy（设计局限，记录不修）

现象：iPhone 进入后台（锁屏）后到点，只有本地通知弹出，FoloToy 不红屏不出声。

根因：recomputeTimer 挂在 RunLoop.main，App 后台被系统挂起时不执行，recomputeStateIfNeeded 不跑，setState(.warning) 不触发，WARNING 命令不下发。本地通知由系统调度，独立触发，故照常弹出。

对策（v0.1 接受）：测试时保持 App 前台；用户点通知唤起 App 后 didBecomeActive → resume() 会补发 WARNING 给 FoloToy。生产模式（35 分钟）下后台无感触发是真实痛点，留作 v0.1+ 改进（后台 BLE 写 / 通知唤起机制），不在本次修。
